## Pros

### 1. Architecture & API Design
- **Single-header API** — consumers only need `libbare.h`. Clean public/private separation.
- **ABI stability contract** — `version` + `struct_size` fields in config structs enable forward-compatible evolution.
- **Opaque handles** (`libbare_account_handle_t`, `libbare_call_handle_t`) hide implementation completely.
- **Event-driven design** with well-typed event union (`libbare_event_t`) is clean and extensible.

### 2. Thread Safety (First-Class)
- All state mutations dispatched to `re_main` via `bare_dispatch()`/`bare_dispatch_sync()` (`dispatch.c`).
- Dedicated event thread separate from `re_main` — prevents consumer deadlocks when calling back into libbare from event callbacks.
- Per-call `tap_lock`, global `acct_lock`, `calls_lock`, `pcap_lock`, `ev_lock` — mutex coverage is thorough.
- `bare_dispatch_sync()` uses stack-allocated context + condvar — no heap, no leaks.

### 3. Memory Management
- Consistent use of baresip's reference-counted `mem_alloc`/`mem_deref`.
- `libbare_queued_event` uses inline 4096-byte buffer for string storage — avoids dangling pointers from transient stack/BA event data.
- Proper destructors (`call_destructor`, `account_destructor`) clean up mutexes and timers.

### 4. Code Organization
- One `.c` file per concern — clear module boundaries (22 source files).
- Clean naming: `bare_*` for internal, `libbare_*` for public API.
- Internal header (`libbare_internal.h`) cleanly separates public from private.

### 5. Cross-Platform Coverage
- Linux, Android (3 ABIs), iOS (xcframework), macOS (universal), Windows.
- iOS Objective-C integration for AVAudioSession is correct (PlayAndRecord, VoiceChat mode for hardware AEC).
- CMake ExternalProject two-pass build correctly handles dependency chain.

### 6. Observability
- SIP trace hook, SDP diff, pcap capture, RTCP stats with E-model MOS — comprehensive.
- pcap writer produces valid Wireshark-readable files with synthetic IP/UDP framing.

### 7. Documentation
- README is thorough: API reference, config reference, consumption examples for CMake/Flutter/Kotlin/Swift/Rust/Python/Go, platform-specific link flags.
- Code comments explain "why" not just "what" (especially `dispatch.c`, `event.c`, `dns.c`, `pcap.c`).

### 8. DNS Resolution
- Full RFC 3263 NAPTR->SRV lookup chain with correct fallback behavior.

### 9. Registration Retry
- Exponential backoff with jitter, configurable max attempts and max delay.

## Cons

### 1. No Unit Tests
- All three test files (`cli_harness.c`, `thread_safety_test.c`, `pbx_compat.c`) are **integration tests** that require a live PBX server.
- No unit tests for individual modules (URL parser, MWI parser, MOS calculation, codec list builder, transport string mapping).
- No mock/stub infrastructure. Cannot test without a live SIP server.

### 2. Pointer Lifetime Contract is Fragile
- `cfg_copy()` in `core.c:14-19` does a shallow `memcpy` of the config struct. All `const char *` pointer fields (server_host, ca_cert_path, auth_user, auth_pass, etc.) are stored by reference.
- Comment says "consumers must keep them alive for the lifetime of the stack" but this is a **silent corruption risk** — no enforcement, no validation, no copy.
- `libbare_account_config_t` fields (`aor`, `auth_user`, `auth_pass`, `display_name`, `outbound`) have the same issue.

### 3. Global Singleton Pattern
- `g_bare` is a single global `struct bare_ctx`. Only one stack per process.
- `s_calls` is a file-scope static in `call.c` with lazy `s_calls_initialized` — not reset on shutdown, preventing re-initialization.
- `s_tap_registered` in `media_tap.c` is a static bool — if init/shutdown/init is called, the filter won't re-register.

### 4. Error Handling Gaps
- `bare_dispatch()` for fire-and-forget operations (hangup, destroy) returns the dispatch error but **not the operation result**. If `ua_hangup()` fails internally, the caller never knows.
- `libbare_account_destroy()` uses `bare_dispatch()` (async) — caller cannot know when destruction completes or if it failed.
- `bare_event_post()` silently drops events on `mem_alloc` failure — no logging or back-pressure.

### 5. Event Queue Unbounded
- `ev_queue` is a linked list with no size limit. Under load (high call volume, verbose logging), this can grow unboundedly, consuming all memory.
- No back-pressure mechanism — if the consumer callback is slow, events accumulate.

### 6. Hardcoded Constants
- `qev->buf[4096]` — inline buffer is 4096 bytes. SIP messages can exceed this (large SDP with many codecs, large NOTIFY bodies). No overflow detection or truncation reporting for some paths.
- `local_sdp[4096]` / `remote_sdp[4096]` in `libbare_call` — same risk.
- `aor[512]` in `account.c` — could be too small for complex URIs with many parameters.

### 7. Phase Labels are Misleading
- The code marks SIP MESSAGE, presence, attended transfer, MWI, 100rel as "Phase 2" in comments, but **all are fully implemented**. This creates confusion about what's actually done vs. planned.
- `headers.c:7-8` says "Per-dialog scoping deferred to Phase 2" but Phase 2 is already complete.
- `dns.c` file header says "(Phase 2)" but it's been implemented.

### 8. MOS Calculation Simplification
- `mos_lq` and `mos_cq` are always equal (`stats.c:87-88`). Conversational MOS should differ from listening MOS (it accounts for round-trip delay asymmetry).
- `LIBBARE_MOS_SIMPLIFIED` enum exists but is never used — only E-model is implemented.

### 9. No Public API for Presence Subscribe
- `libbare_account_publish_presence()` sends PUBLISH, but there's no public API to **subscribe** to a buddy's presence. BLF relies on baresip's contact module being pre-configured, which isn't exposed through the SDK API.
- `contact_update_handler` fires for all contacts globally (`ps->account = NULL`) — no way to associate with a specific account.

### 10. pcap Limitations
- Always writes SIP as UDP framing (`is_udp` parameter ignored at `pcap.c:144`). TCP/TLS/WS SIP messages will appear as UDP in Wireshark.
- No RTP/RTCP capture despite the README implying richer pcap support.

### 11. No Callback Removal/Cleanup for Event Callback
- `libbare_init()` takes `event_cb` as part of config. No way to change or remove the callback at runtime without full shutdown+reinit.
- `libbare_call_set_media_tap()` with `cb=NULL` removes a tap, but there's no mechanism to know when the last audio frame has been processed after removal (race window).

### 12. `ensure_calls_init()` Lazy Initialization
- `s_calls_initialized` is checked without synchronization. In theory, two threads could race on first call to `bare_call_find()`. In practice, this happens during init, but it's technically unsafe.

### 13. Missing Validation
- `libbare_account_create()` doesn't validate `auth_pass` is non-NULL — a NULL password would silently fail during registration.
- No validation that `audio_codec_count` is within `[0, 8]` bounds.

---

## Summary

**libbare is a well-architected, production-quality VoIP SDK wrapper** with excellent thread safety, clean API design, comprehensive feature coverage, and thorough documentation. Both Phase 1 and Phase 2 are fully implemented.

The main areas for improvement are:
1. **Testing** — needs unit tests with mock infrastructure
2. **String ownership** — config pointer fields should be deep-copied
3. **Global state cleanup** — statics prevent re-initialization
4. **Phase labeling** — update comments to reflect actual implementation status
5. **Presence subscribe API** — missing public API for buddy subscription
